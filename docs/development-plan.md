### MoonBit 实现方式

- 格式编码、长度与偏移检查集中到独立模块，生成与应用共用这些规则。
- 索引使用整数数组和原始字节视图，不为每个后缀复制完整字节串。
- 后缀排序先对照原版 qsufsort 的结构与不变量实现；如改用倍增加基数排序，记录替换原因并用独立小数据预期验证。
- 匹配扫描、前后向匹配、重叠调整和控制三元组形成可独立测试的私有函数。
- bzip2 通过窄适配层调用已发布 MoonBit 包，压缩细节不扩展成第二个自研项目。
- 库不进行文件 IO，不调用 C 程序、Python 或远程服务。参考程序和 Python 仅参与测试及数据生成。
- 参考程序需要的头文件或构建适配单独保存补丁与哈希；算法修改不能混在“平台适配”中。

## 四 数值、格式与行为契约

### 文件头与整数编码

1. 文件头固定为 32 字节，开头八字节为 ASCII `BSDIFF40`。
2. 后续三个八字节字段依次表示压缩后的控制块长度、压缩后的差分块长度和恢复文件大小；新增块占补丁剩余部分。
3. 格式整数采用小端的符号与数值分离编码，最高字节最高位表示负号，不是普通二进制补码。
4. 编解码覆盖零、负零输入、正负值及最大可表示幅值。编码不能直接对 Int64 最小值取负数；它不在该格式的可编码范围内。
5. 文件长度和偏移先用受检查的 Int64 计算；转换为数组索引前再确认非负、在缓冲区内且不超过目标平台和资源上限。
6. 压缩块长度和新文件大小必须非负；`32 + 控制长度 + 差分长度` 等运算逐项防溢出并检查实际补丁边界。

文件头声称可以表示很大长度，不等于本库能在内存中处理完整范围。实际支持规模由数组上限和资源限制共同决定。

### 控制指令与恢复语义

控制块由三元组 `(x, y, z)` 组成，每个分量使用上述整数编码：

- 取差分块的 x 字节，与旧文件对应字节相加，结果按模 256 写入新数据。
- 取新增块的 y 字节直接写入新数据。
- 旧数据游标在已经前进 x 字节后，再按有符号 z 调整位置。

x、y 必须非负，z 可以为负。每次推进检查新文件剩余空间、差分和新增块剩余数据及整数范围。旧文件范围外的字节贡献按参考语义视为零，不能因为旧游标暂时为负或超出末尾就无条件拒绝合法补丁。

允许只调整旧游标而不增加输出的合法控制指令；通过控制数据上限、指令次数和工作量限制终止异常输入，不能粗暴把所有零输出指令判错。

空旧文件、空新文件和两者均空分别处理。成功恢复空文件是合法结果，不是“没有执行”或错误占位。

### 压缩块与封装边界

三个块分别是一条完整的 bzip2 流，空块也采用合法空流。生成器首版固定使用级别 9，避免提前增加调优参数；依赖探针的级别 1 成功不能替代级别 9 的正式验证。

适配层需要确认解压上限、完整结束和校验和检查的实际行为。首版采用明确的单流封装：拒绝不完整流、校验失败、拼接流和段内尾随杂字节，且不允许解压绕过预算。控制块按 24 字节对齐，成功应用后不保留未使用控制指令、差分或新增数据。

这是有意采用的严格封装策略。部分宽松参考程序可能忽略尾随或冗余数据，不能据此要求本库接受全部这类输入；`docs/compatibility.md` 要明确这项差别。Commit 4 必须确认依赖能提供所需的流结束及消费边界信息，不能只凭解压返回成功推断完整消费。

若现有依赖无法支持这项检查，先记录具体缺口并评估小范围适配或替换依赖；不自行悄悄降低检查，也不借机重写整个 bzip2 引擎。

### 确定性、完整性与兼容性

- 同一旧数据、新数据、选项和固定依赖版本应产生稳定结果，数据中不引入时间戳。
- 与上游互操作比较恢复后的完整字节，不要求补丁字节、控制段划分或补丁大小完全相同。
- BSDIFF40 本身不含旧文件和新文件的密码学哈希。CRC 校验压缩数据，不等于验证调用者选对了旧文件。
- 首版不承诺识别所有旧文件不匹配；实际应用方应在外层验证旧文件与恢复结果的预期哈希。示例必须展示结果校验。
- 输入字节不被修改，调用失败不返回部分成功结果。API 不隐式退出进程。

### 资源限制与错误

限制至少覆盖旧数据、新数据、补丁、解压总量、控制数据/指令数量，以及主要匹配和排序工作。上限在分配、扩张、解压和循环处理前生效，不能在数据已全部展开后才检查。

默认限制的具体数值在 Commit 6 与 Commit 11 根据实际资源测量固化，并写入文档及边界测试。无界处理不能通过零或负值隐式开启；测试可以传入较低上限验证恰好够用和差一单位。

MoonBit 可控循环的工作计数不等于 bzip2 内部的完整 CPU 预算；首版不声称具备严格墙钟超时、实时性或整个进程的峰值内存保证。

错误至少区分无效配置、格式不支持、截断数据、非法字段、整数溢出、解压失败、输出越界和资源超限。保留阶段、块类型和可定位偏移，不把损坏输入转换成空补丁或空新文件。

### 拟定公开接口

以下是接口设计草案，不是已经编译通过的 MoonBit 声明；最终以工具链检查和生成的 `.mbti` 为准。

```text
BsdiffError / ErrorStage / Limits

diff(old_bytes, new_bytes, limits)
    -> Result[Bytes, BsdiffError]

apply(old_bytes, patch_bytes, limits)
    -> Result[Bytes, BsdiffError]
```

首版公开入口围绕 diff 与 apply。后缀数组、压缩适配、控制指令和格式拼装先保持私有，不为了展示内部结构扩大长期维护的 API。

### CLI 行为

拟提供以下接口；这些是目标用法，不是已经可执行的命令：

```text
moonbsdiff diff OLD_FILE NEW_FILE PATCH_FILE
moonbsdiff patch OLD_FILE PATCH_FILE OUTPUT_FILE
moonbsdiff --help
moonbsdiff --version
```

- 文件按二进制读取；读取前检查可得的大小，读取中仍执行上限检查，避免文件变化绕过限制。
- 默认拒绝覆盖已有输出文件，拒绝输出与输入指向同一文件；本版不增加强制覆盖开关。
- 成功前在目标目录使用独占创建的临时文件；完整写入、关闭后以不覆盖已有目标的方式交付结果。失败清理本次临时输出，不删除已有文件。
- 成功退出码为 0，参数错误为 2，运行失败为 1；错误写入标准错误。
- 帮助说明本工具子命令的参数顺序，不能把它与上游 bspatch 的 `OLD NEW PATCH` 顺序混淆。
- Windows 与 Linux 的路径、非 ASCII 文件名、目标已存在和读写错误分别测试，不以路径字符串不相同代替必要的同文件检查。

## 七 测试与比较方法

### 输入输出比较

成功路径以恢复结果与原始新文件逐字节相等为准。大文件报告可附 SHA-256，但生成报告的工具不能只使用被测库自己计算的预期。

补丁内容不与上游做全字节强制一致比较；不同匹配或压缩输出可以合法互操作。生成器是否真正差分，还要用有明显可复用内容的固定样例检查控制和差分结构，避免全量新增实现通过自往返。

### 必须覆盖的矩阵

| 维度 | 案例 |
| --- | --- |
| 空输入 | 旧空、新空、同时为空、空目标补丁 |
| 编辑 | 相同、替换、插入、删除、前后追加、截短、块移动 |
| 字节 | 0x00、0xff、全部字节值、UTF-8、周期和长重复串 |
| 匹配 | 相同最长匹配、末尾匹配、交叠、负 seek、旧区间外零贡献 |
| 压缩 | 空流、级别 1/9、块边界、跨块、CRC 错误、截断、单流边界 |
| 格式 | 短头、错误魔数、符号幅值边界、负长度、溢出、错位控制 |
| 消费 | 数据不足、额外控制、额外差分/新增数据、零输出指令 |
| 资源 | 各限制、恰好够用/差一单位、累计工作、失败重试 |
| API | 输入不变、结果隔离、重复调用、结构化错误 |
| CLI | 路径、中文文件名、同文件、已有输出、读写失败、退出码 |
| 互操作 | 上游生成/本库应用，本库生成/上游应用，各目标分别记录 |
| 分发 | 干净源码、候选包、Mooncakes 注册表版本的独立调用 |

### 性质测试与独立预期

自往返 `apply(old, diff(old, new)) == new` 是必要检查，但不足以证明格式兼容。格式编码、后缀数组和负偏移等关键规则都应有来自其他实现或人工可推导的预期。

随机测试固定种子、保存完整输入，真实失败案例进入回归目录。异常案例不能统一接受任意错误；需要检查是否落到预期错误类别、是否保留相关阶段以及是否影响后续调用。

测试数量由覆盖矩阵决定，不先承诺虚构的总数，不把同一输入在三目标重复执行计作三份独立参考数据。

## 八 检查命令与持续集成

以下是未来仓库的实施要求，不代表已经执行。每个步骤只运行与变化相适应的检查，发布前再跑完整矩阵。工具链与脚本版本固定在仓库中。

日常维护：

```text
moon info
moon fmt
moon fmt --check
git diff --check
git diff --exit-code -- "*.mbti"
```

`moon info` 后先审阅预期接口变更；CI 的接口检查在仓库已包含正确生成文件时执行，不能为了检查通过把所有接口差异直接接受。

核心功能完成后的跨目标检查：

```text
moon check --target native --deny-warn
moon build --target native
moon test --target native --deny-warn

moon check --target js --deny-warn
moon build --target js
moon test --target js --deny-warn

moon check --target wasm-gc --deny-warn
moon build --target wasm-gc
moon test --target wasm-gc --deny-warn
```

native CLI 包需正确声明目标范围；如果工具链要求按包选择构建，脚本显式选择支持的包，不能把正常的 native 专用范围当成核心库跨目标失败，也不能靠全局跳过隐藏核心失败。

对照和验收脚本完成后，拟提供：

```text
python scripts/check_reference.py --manifest testdata/manifest.json --strict
moon run cmd/example --target native
python scripts/check_acceptance.py
```

脚本应实际执行并核对结果，拒绝缺失日志、零测试、未执行案例和过期报告。没有加入脚本的检查不能在 README 中声称由 CI 覆盖。

本次仅编写规划文件，不运行未来项目的代码测试；已有依赖探针和源码归档核验单独记录。

## 十 风险与处理方式

| 风险 | 处理方式 |
| --- | --- |
| 源码下载不可用或被替换 | 锁定原始归档哈希，使用可核验镜像，下载失败与哈希不符都停止参考生成 |
| 原版 C 的错误检查不足 | 合法输入用作兼容参考，损坏输入按独立安全契约验证 |
| 符号幅值当作补码读取 | 独立编码向量、负零和幅值边界测试 |
| 负位移或旧区间外读取处理错误 | 锁定参考语义，构造人工补丁，验证零贡献及安全偏移 |
| 自往返隐藏两边相同错误 | 双向实际互操作，独立格式解析和原始目标字节比较 |
| 后缀排序对重复数据退化 | 完整后缀数组预期、重复串案例、工作计数与规模基线 |
| 生成器变成完整新文件压缩 | 检查可复用样例的控制结构、差分与大小，不以单纯可恢复判定完成 |
| bzip2 包忽略尾随数据或未落实限制 | Commit 4 单独验证消费和结束能力，缺口有记录后修复，不凭 API 名称推断 |
| 缓冲区和解压占用超预期 | 分配前限制、解压总量和实际资源记录，明确完整缓冲区模型 |
| CLI 写失败破坏现有文件 | 独占临时文件、不覆盖交付、同文件检查、失败清理测试 |
| 用户误以为补丁会验证旧文件身份 | 文档明确 BSDIFF40 无内置文件哈希，示例展示外部完整性校验 |
| 测试或发布证据与最终源码不一致 | 记录源码 SHA、CI SHA、包哈希和注册表版本，发布后文档分开记账 |

## 十二 首版完成判断

MoonBSDiff `0.1.0` 的完成标志是：外部 MoonBit 项目能够安装已发布版本，调用 diff 生成真实 BSDIFF40 补丁，调用 apply 恢复预期新数据；与固定上游的两个互操作方向均有独立证据，声明范围内的失败有明确错误和资源边界，CLI、示例、README、许可证、包与最终源码 CI 一致。
